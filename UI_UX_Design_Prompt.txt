TOURISTO — UI/UX DESIGN PROMPT

Design a polished, modern, responsive tourism marketplace called "Touristo".

Touristo is a Pakistan-first tourism marketplace connecting travelers with tour companies and tour guides.

The interface should feel trustworthy, premium, modern, welcoming, and easy to use.

---

1. PRODUCT

---

Touristo helps travelers:

* Discover Pakistani destinations
* Explore tour packages
* Compare tour companies
* Discover and compare tour guides
* Plan trips using AI
* Submit tour bookings
* Manage trips
* Communicate with tour companies
* Check weather information
* Use emergency SOS/location sharing

Tour companies can:

* Manage their company profile
* Create and manage tour packages
* Manage bookings
* Manage tour guides
* Respond to traveler inquiries

---

2. TARGET USERS

---

Primary:

* Pakistani travelers
* Domestic tourists
* Students and young travelers
* Families
* Small travel groups
* Adventure travelers

Secondary:

* Tour companies
* Tour operators
* Tour guides

---

3. DESIGN STYLE

---

Create a:

* Modern
* Clean
* Premium
* Travel-focused
* Trustworthy
* Friendly
* Responsive
* Professional

experience.

Avoid:

* Overcrowded layouts
* Excessive text
* Unnecessary decorative elements
* Inconsistent colors
* Huge blocks of information
* Outdated mobile-app patterns

Use strong visual hierarchy and generous spacing.

---

4. BRAND / COLOR

---

Use the existing Touristo project theme.

Do NOT introduce a new blue/green/orange palette.

Use the application's semantic theme variables:

--surface-primary
--surface-secondary
--text-primary
--text-secondary
--border-primary
--accent-primary

Use semantic success/warning/error colors only where necessary.

The overall interface should remain visually consistent across all screens.

---

5. TYPOGRAPHY

---

Use a clean modern sans-serif font.

Recommended hierarchy:

H1:
28–32px, bold

H2:
20–24px, semibold

Card titles:
16–18px, semibold

Body:
14–16px

Supporting text:
12–14px

Buttons:
14–16px, medium/semibold

10. HOME SCREEN

---

The Home screen should immediately communicate:

"Discover Pakistan. Find the right trip."

Include:

* Greeting
* Search
* Featured destinations
* Recommended packages
* Popular packages
* Destination cards
* Host/company discovery
* AI Planner entry point

Cards should remain compact and visually clear.

---

11. DESTINATION EXPERIENCE

---

Destination Explore should contain:

* Hero image
* Destination name
* About
* History
* Culture
* Famous places
* Local food
* Available tour packages

Use clear sections and whitespace.

---

12. PACKAGE DETAIL

---

Package Detail should include:

* Large package image
* Package title
* Host/company
* Verification badge
* Rating
* Price
* Duration
* Location
* Description
* Inclusions
* Exclusions
* Itinerary
* Tour guides
* Reviews
* AI review summary when available

Primary actions:

BOOK NOW

CHAT WITH HOST

SAVE

Do NOT add a pre-booking "Chat with Guide" button.

---

13. HOST COMMUNICATION

---

Messaging is:

Traveler ↔ Host

The traveler can start a conversation from Package Detail.

The host can manage customer inquiries from the Host Dashboard.

Inbox should display:

* Host/company identity
* Verification
* Last message
* Timestamp
* Unread count
* Package context
* Message history
* Message composer

Do not design unsupported voice-call or file-attachment functionality as current features.

---

14. TOUR GUIDES

---

Tour guides are displayed as informational/matching resources.

Show:

* Photo
* Name
* Specialty
* Rating

Allow:

* Search
* Filtering
* Comparison
* Matching

Guide communication can be introduced later for active/paid trips.

---

15. BOOKING

---

Booking screen should contain:

* Package summary
* Travel/start date
* Number of travelers
* Special requests
* Price calculation
* Payment method selection
* Booking submission
* Confirmation state

The current MVP does not contain a live payment gateway.

Do not present a fake external payment integration as already implemented.

---

16. AI TRIP PLANNER

---

Create a conversational travel assistant.

Users can ask:

* Where should I travel?
* Which destination is best?
* Suggest a trip for my budget.
* What can I do in Hunza?
* What should I visit in Skardu?

Support:

* English
* Urdu
* Roman Urdu

The assistant should have:

* User messages
* AI responses
* Loading state
* Error state
* Suggested prompts

---

17. MY TRIPS

---

Show:

* Upcoming trips
* Booking information
* Package
* Travel date
* Number of travelers
* Booking status

Use clear status indicators.

---

18. WEATHER

---

Show:

* Current temperature
* Feels-like temperature
* Humidity
* Wind
* Forecast
* Simplified road status

Use clear weather cards and icons.

---

19. SOS

---

The SOS interface should prioritize safety and clarity.

Include:

* Get Current Location
* Latitude
* Longitude
* Google Maps link
* Share/Copy location
* Regional emergency/tourism information

Do not imply automatic emergency dispatch.

---

* Booking management
* Tour-guide management

Customer Inquiries should be a prominent dashboard action.

22. UI QUALITY

---

Every screen should include appropriate:

* Loading state
* Error state
* Empty state
* Hover state
* Focus state
* Disabled state

Use:

* Consistent border radius
* Subtle shadows
* Consistent spacing
* Strong typography hierarchy
* Clear CTA buttons

The final interface should look like a professional production-ready tourism marketplace rather than a basic student prototype.

25. FINAL DESIGN GOAL

---

The final Touristo experience should make a traveler feel:

"I can discover a place, find a trustworthy tour company, understand the package, talk to the host, book my trip, manage it, and stay informed — all from one platform."

Prioritize usability, trust, clarity, responsiveness, and visual polish over unnecessary decoration.
